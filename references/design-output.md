# 设计出图与修订

## 先从偏好做方案

- 看用户提供的是销售图、现场量房图还是现场照片。记录来源、版本、可靠尺寸及待复尺项。门窗、柱梁、管井、固定点和保留构件先录入底图。有冲突时保留来源和差异。有尺寸才标可复算的净距；仅有截图时可画概念布局，标明「无可靠比例／待复尺」。
- 用用户的原话梳理怎么住、什么必须保留、什么可以取舍，把偏好落实成可在图上核对的要求。例如「两人一起备菜」落实到连续操作台、洗碗机门展开及通道；「经常六人吃饭」同时画家具本体、椅子拉出范围和从玄关到餐区的路径。
- 先给可讨论的推荐稿。确有取舍时做一个对照方案，共用同一底图、尺度和视角，写清差异、代价和待确认项。缺少的信息只补问会改变当前选择的部分。

## 只有销售户型截图时

1. 先标出截图能辨认的房间、开口和相互位置。截图中的建筑面积、家具符号和像素距离不能当作室内净尺寸。墙体性质、管线或标注看不清时写「未确认」；涉及这些部位的改动设为待核验条件。
2. 用户要比较方案时，可在同一张底图上直接画两套概念布局。标出关键家具、出入口、日常动线和对比编号。给每案写一条偏好兑现、一条取舍和一条可能改变推荐的复尺项。仅有截图的图面标「概念布局 · 无可靠比例」，不标推算出的实尺、通道净距或可下单尺寸。文字模式可用房间分区示意或表格表达同样的信息。
   - 交付单个 SVG 时，自带底图：用矢量绘制清楚的轮廓和开口，或嵌入实际截图。图稿避免引用下载后会丢失的本地图片。图例预留内边距，长句按语意显式分行（例如用 SVG 的 `tspan`），图例变高时同步增大面板及画布。交付前在实际渲染结果里检查墙线、开口和比较标记，检查最长文字的末尾和最后一行都在框内；发现裁切便调整后重新渲染。
3. 把假设和复尺项留在方案记录里。要复尺时说明量哪两边、用于判断哪项选择。用户补了个别实尺时，只更新有依据的图层和相关判断，其余未知部分继续标注。

## 三类图用同一版数据

保存一份项目方案记录，格式可用 Markdown 或结构化文件。至少含底图版本、当前方案号、尺寸及来源、各物件或点位的稳定标识、用户已确认事项、材料、视角、待确认项和本轮改动。使用坐标时写明原点、轴方向和物件定位基准（例如矩形家具的角点或中心）；基准含糊且会改变净距或点位时，先确认或把结果标为基于假设。用该记录生成或校对同一版的图，用户可以带着记录续作。

| 图 | 输出和检查 |
| --- | --- |
| 平面方案 | 用客户端可用的方式输出二维图，例如 SVG。画出固定构件、拟放家具、开门及操作范围。量通道时写清在哪两条边之间、门扇或椅子是什么状态 |
| 空间效果 | 沿已选平面固定视角，标明材质、色彩和照明意图。可用简化轴测，也可用客户端已有的图像工具生成概念效果。发布前逐项对照开口、柜体、桌椅和朝向；对不上先修正，无法修正时指出差异并保留可信的示意 |
| 交底示意 | 标注需要现场核对的灯位、插座、厨卫给排水、柜体和设备接口。关联到具体房间、物件、方案号、复核人和工序；把暂定定位、复尺要求及最终签认分开记录 |

缺少文件生成或预览能力时，交付能核对的方案、点位表和所需补图。结构、机电和施工尺寸以现场复尺及有相应资质的人员确认结果为准。

## 收到反馈后

1. 加载用户指定的上一版及已确认事项。从文字或圈注识别房间、物件、操作及保留项。只有定位歧义会导致误改、或改动与已确认要求冲突时才追问。
2. 用新版本记录反馈、实际改动和依赖项。布局改动后重算净距，复核灯位、插座、柜体和设备接口，标出影响报价或下单的事项。只改材质时保留几何、视角和没有受影响的点位；材质厚度或安装条件会影响净尺寸时另列待复尺。
3. 交付新版和简短差异说明。逐项核对用户要求保留的内容、平面与效果的一致性，以及交底示意上是否仍显示旧点位。沿用旧图时写清对应的版本。

## 从圈注或标记续改

1. 先读截图上可见的方案号，与方案记录的编号对照。截图裁切或没有编号时，用开口、固定柜、相邻物件和圈中对象的**原位置**比对；仅能看出物件名称相同还不足以确认底稿。同一物件在截图和记录中的原位置不一致时，视为版本冲突。
2. 版本冲突、圈中可能有多个对象，或反馈会改到已确认的对象时，只问清该处，暂不生成新版。编号不一致时直接指出截图版与记录版，请用户确认哪个是底稿。对齐后，将圈和箭头对应到物件标识。文字决定操作，圈注辅助定位。箭头只表示方向，像素距离不换算成现场位移。保留未点名且不受影响的物件。
3. 交付同视角前后图或带旧轮廓、新轮廓及移动箭头的叠图。方案记录留存前后版本、原反馈、物件标识、保留项、受影响点位及其状态。对可能移动而尚未定的位置写「待复核」，不把新位置直接记为施工确认。用户只有上一版记录和圈注时也按此续作；无法读图时，请用户补物件标识和要挪向的参照物。
